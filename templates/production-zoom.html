Tool notes What each tool does, when it helps, and whether you need it
PACKAGE

Docker

Builds an image containing your inference app and its runtime dependencies. A container is a running instance of that image.

Useful when you package or host the serving app yourself. It is not the only way to deploy a model.
ORCHESTRATE

Kubernetes

Runs containers as Pods, maintains the desired number of copies, and gives Services stable names for routing.

Useful when your team operates container workloads. A managed endpoint can handle this layer.
EVENT STREAMING

Kafka

Producers write events to topic logs; consumers read them independently. Configured retention lets consumers replay events within the retention window.

Useful for continuous event streams and replay. It is not needed for a direct prediction API.
MANAGED MESSAGING

Pub/Sub

Publishers send messages to topics; subscribers receive them through subscriptions and acknowledge processing.

Useful for decoupled background work when you want a managed messaging service. Its delivery model differs from Kafka.
WORKFLOWS

Airflow

Develops, schedules, and monitors workflows made of dependent tasks.

Useful for recurring batch data, training, and evaluation jobs—not for answering each live prediction request.
WORKFLOWS

Flyte

Runs and tracks data and machine-learning tasks and workflows.

Useful for repeatable ML or data jobs. It does not have to sit in the model’s request path.
STORE IMAGES

Container registry

Stores built container images so a server or deployment platform can pull and run them.

Examples include Docker Hub and cloud registries. This stores app images, not model approval history.
TRACK MODELS

Model registry

Tracks model versions and their lineage so a release can be identified and promoted.

Useful when comparing, approving, or rolling back model versions. It does not host the live API.
